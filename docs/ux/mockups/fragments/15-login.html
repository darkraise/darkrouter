Sign in — the three states

1 resting 1 · Resting — GET /api/auth/status decides whether this screen renders at all. Sign in is POST /api/auth/login {"password"}, behind a same-origin check that answers 403 "cross-site request refused" before the password is read. Success rotates the session id, then sets darkrouter_session — HttpOnly, SameSite=Lax, Secure only under TLS, 30-day sliding expiry.

One operator, one password. There is no account list, no reset link and no second factor — the only credential this console has is the hash in the environment.

2 rejected 2 · Rejected — 401 {"error":"invalid password"}. One string for a wrong password AND for an unconfigured hash. VerifyPassword fails closed on an empty or malformed hash, so bcrypt (cost 12) is never even reached in the second case and the two answers are indistinguishable from outside.

The same sentence answers a wrong password and a gateway with no hash configured at all. Which of the two it was is deliberately absent: an operator who read that no password is set would have learned the port is open, and so would anyone else who reached this box.

No lockout and no attempt counter today. The cost of a guess is one bcrypt verification at cost 12, which is the only rate limit there is.

3 no password configured 3 · Unconfigured — NEW, and the one state the product fails at. Today the unset variable only appends a line to the startup warnings /healthz reports, admin.New is handed an empty PasswordHash, and the login box answers 401 forever with no way to tell why. This banner needs GET /api/auth/status to report configured:false, and the server serves it only to a request arriving on the loopback interface, so the 401 in state 2 stays the only answer a remote browser ever gets.

sign-in is closed

No admin password hash is configured on this gateway, so every password is refused — including the right one. The proxy keeps serving; only the dashboard is shut. Three steps on the machine running it:

1

Generate a hash with the binary you already have. bcrypt, cost 12. With no -password it reads from stdin, so the password stays out of shell history.

darkrouter hash-password
2

Put the printed value in the environment.

DARKROUTER_ADMIN_PASSWORD_HASH $2a$12$K7dRz9mQv1uYxJ4pC2sHwO…Bn6TcSk1e
3

Restart. The variable is read once at startup; a config reload does not pick it up.

docker compose restart darkrouter

if the value goes through compose

A bcrypt hash always contains $, and docker compose reads each one as the start of a variable while it loads .env. Double every one of them, or the value silently arrives truncated and the correct password still fails with the message in the middle column.

as hash-password prints it $2a$12$K7dRz9mQv1uYxJ4pC2sHwO…Bn6TcSk1e
as compose must receive it $$2a$$12$$K7dRz9mQv1uYxJ4pC2sHwO…Bn6TcSk1e

Identity mark

44 · Identity mark — inline SVG built from rects on a 24 grid, two tokens only: a --bezel hairline and one --trace pip. No curve, no gradient, no fetched file, so the favicon, the rail brand and the 96px sign-in mark are one figure at three scales rather than three assets to keep in step.

96px — sign-in
24px — inline
16px — favicon

The routing ladder and the logo drawn as the same figure: a bezel around a spine, three candidates entering from the left, two of them stopping at a hollow skip mark on the spine, and the third crossing it and running out to a single bright pip that breaks the frame. That is one request walking a failover chain, and it is also the instrument itself — a screen with something on it.

At 16px the interior detail drops out and what survives is a bracket, a crosshair and one dot pushed right, which is enough to find the tab by. It is the only place in the product where --trace appears without a routing decision behind it, and it is doing the same job: marking the one candidate that came out.

24 grid, rects only, no curve and no gradient. Bezel square (2,2)–(22,22) · spine 1px at x=12 · stubs 1px at y=7, y=12 and y=17, the outer two stopping at x=12 and the middle one crossing to x=19 · skip marks 3×3 hollow, centred on the spine at (12,7) and (12,17) · pip 4×4 filled, centred at (20,12), the one element in var(--trace).

One deviation from the written geometry, and it is visible above: the spine breaks either side of each skip mark instead of running unbroken from y=2 to y=22. A 3×3 outline drawn with a 1px stroke has a 1px core, which a 1px rule through it fills exactly — the two marks would render solid at every size and read as served rather than skipped, inverting the figure's meaning.
