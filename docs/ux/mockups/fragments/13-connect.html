33 · GET/POST/DELETE /api/proxy-tokens. New. server.proxy_token today is a single shared secret compared constant-time after SHA-256, accepted in all three dialects' auth headers.

Proxy tokens

Today darkrouter authenticates against one shared secret — server.proxy_token in the config file, with no rotation and no per-client keys.

Every client below would be holding the same string, so a single leaked token cannot be revoked without reconfiguring every client at once. The table below is what per-client tokens look like once a proxy-token endpoint exists; it is not what the router does today.

The value is shown once, at creation. The console stores only its SHA-256 and can never display it again — which is why every row above, and every snippet below, shows a mask rather than a secret.

Claude Code shell environment 
export ANTHROPIC_BASE_URL=http://192.168.0.10:8080
export ANTHROPIC_AUTH_TOKEN=<your-proxy-token>

No /v1 on the base URL — Claude Code appends /v1/messages itself. ANTHROPIC_AUTH_TOKEN leaves as Authorization: Bearer; ANTHROPIC_API_KEY would leave as x-api-key. The anthropic dialect accepts either.

The other five tabs

Codex ~/.codex/config.toml 
model = "openai/gpt-oss-120b"
model_provider = "darkrouter"

[model_providers.darkrouter]
name = "darkrouter"
base_url = "http://192.168.0.10:8080/v1"
env_key = "DARKROUTER_TOKEN"
wire_api = "responses"

Codex reads the secret from the environment variable named by env_key, so the token is exported rather than written into the file. wire_api = "responses" targets POST /v1/responses.

Cursor Settings › Models 
Override OpenAI Base URL   http://192.168.0.10:8080/v1
OpenAI API Key             <your-proxy-token>

Cursor has no config file for this — both fields are typed into Settings. Its Verify button calls GET /v1/models, which the router answers from its own catalog rather than forwarding.

OpenAI SDK python 
from openai import OpenAI

client = OpenAI(
    base_url="http://192.168.0.10:8080/v1",
    api_key="<your-proxy-token>",
)

base_url keeps /v1 here: this SDK appends /chat/completions to whatever it is given. api_key leaves as Authorization: Bearer, which is the only form the openai dialect reads.

Anthropic SDK python 
from anthropic import Anthropic

client = Anthropic(
    base_url="http://192.168.0.10:8080",
    api_key="<your-proxy-token>",
)

base_url stops at the origin: this SDK appends /v1/messages. api_key leaves as x-api-key, which the router prefers when a client sends both headers.

curl 
curl -i http://192.168.0.10:8080/v1/chat/completions \
  -H "Authorization: Bearer <your-proxy-token>" \
  -H "Content-Type: application/json" \
  -d '{"model":"openai/gpt-oss-120b","messages":[{"role":"user","content":"ping"}]}'

The -i is what prints the four headers below, so a client can read the routing decision without opening this console at all.

55 · Headers — set by the proxy on every response; the terminal-visible half of the trace.

Response headers

Off the wire one response, three attempts 
HTTP/1.1 200 OK
Content-Type: application/json
X-Darkrouter-Provider: cerebras
X-Darkrouter-Model: openai/gpt-oss-120b
X-Darkrouter-Attempts: 3
X-Darkrouter-Request: 01M0W4WBNR5N8XW2VR6MBD3HYA
What each one tells you
X-Darkrouter-Provider Which provider actually answered — not necessarily the first candidate the ladder offered.
X-Darkrouter-Model The upstream model id that provider was asked for, after any alias the request used was resolved.
X-Darkrouter-Attempts How many candidates were tried before one answered; a request that never reached a provider reports 0. Anything above 1 is what the request log marks failover ×3
X-Darkrouter-Request The ULID to paste into operate/requests to read the whole ladder, including the attempts that failed.

A fifth header, X-Darkrouter-Estimated: true, appears only on the responses whose token counts the router had to estimate rather than read back from the provider.
